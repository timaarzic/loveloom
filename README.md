# LoveLoom · beta 0.6

Облачная beta веб-приложения для двух участников. Создание комнаты пока бесплатное; платёжного экрана и списаний нет.

## Публичная beta

После публикации приложение доступно по адресу:

<https://timaarzic.github.io/loveloom/>

Это уже не демонстрационная комната. Приложение начинает работу с настоящей регистрации или входа, затем показывает экран с действиями «Создать комнату» и «Войти в комнату». Аккаунты, комнаты, переписка и общие записи сохраняются в Supabase. Сессия хранится на устройстве, поэтому после закрытия вкладки или установленного приложения пользователь возвращается в свою комнату.

Для проверки пары нужны две разные почты и два браузера либо обычное и приватное окно. После регистрации подтвердите почту по письму, затем войдите. Используйте отдельный пароль, который не применяется в других сервисах.

GitHub Pages автоматически пересобирает beta при обновлении ветки `main`. Статическая страница подключается напрямую к Supabase через публичный publishable key; доступ к данным защищён не ключом в браузере, а серверными функциями PostgreSQL, проверкой `auth.uid()` и RLS.

## Что работает в облачной beta

- Настоящая регистрация по почте, подтверждение почты, вход, выход, восстановление пароля по одноразовой ссылке и сохранение сессии на устройстве.
- Отдельный экран после входа: бесплатное создание комнаты или вход по её уникальному паролю.
- Уникальность паролей комнат, один аккаунт в одной комнате и максимум два участника проверяются атомарно в базе.
- Третий участник получает сообщение «У нас все дома — в комнате уже двое».
- Комната сразу сохраняется в PostgreSQL и восстанавливается после обновления страницы, закрытия браузера и повторного входа.
- Пароль комнаты нормализуется для поиска, хранится как digest для проверки уникальности, а отображаемое значение — в зашифрованном секрете Supabase Vault. Открытый пароль не хранится в таблице комнаты.
- Создатель может удалить комнату у обоих. Приглашённый участник может выйти; общая история удаляется у обоих, а повторный вход начинает пустую историю.
- Главная панель, два счётчика, общий часовой пояс, имя второго участника и настройка виджетов на устройстве.
- Чат с текстом, фотографиями, видео и голосовыми сообщениями, ответами на конкретное сообщение, шестью реакциями, плавным появлением и тематическим статусом прочтения. Синхронизация двух устройств использует закрытый канал комнаты и резервную проверку базы. Лимит — 1000 сообщений: после него база автоматически удаляет самые старые записи истории. Новые голосовые записываются как моно WAV 16 кГц, поэтому одинаково воспроизводятся в Safari/iPhone и Chromium; слишком короткие или пустые записи не отправляются.
- Закрытый общий фотоальбом. Оригиналы находятся в приватном Supabase Storage, поддерживаются обычные и мобильные HEIC/HEIF-фотографии, а приложение получает временные подписанные ссылки только для просмотра.
- Капсулы времени: содержание скрывается сервером до выбранного момента открытия. В комнате хранятся три последние капсулы; новая атомарно удаляет самую старую.
- Общий виртуальный сад, который каждый участник может полить один раз в сутки по часовому поясу комнаты. Иллюстрация растёт на 30, 50 и 100 общих поливах.
- «Тактильность»: когда раздел открыт у обоих, нажатие фирменного сердца передаёт эфемерный realtime-сигнал, сохраняет прежние мягкие волны вокруг логотипа, рассыпает по всему экрану нарисованные сердца и поцелуи и включает вибрацию на поддерживаемом устройстве. Сигнал не сохраняется.
- Web Push для новых сообщений: разрешение запрашивается только по кнопке в настройках, подписка отдельна для каждого устройства, а после включения сразу приходит контрольное уведомление. Приложение обнаруживает потерянную сервером подписку и создаёт её заново; текст личного сообщения на экране блокировки не показывается. На iPhone LoveLoom нужно сначала добавить на экран «Домой» и открыть как веб-приложение.
- Счётчик непрочитанных сообщений хранится в базе отдельно для каждого участника. Вне чата красный бейдж над иконкой показывает число новых сообщений, а при открытии чата отметка прочтения синхронизируется между устройствами.
- Общие события, текстовые воспоминания, заметки, желания, списки фильмов и музыки.
- Четыре мини-игры по 20 уникальных вопросов каждая. Раунд открывается в отдельном адаптивном экране, а ответ партнёра остаётся скрытым до ответа обоих.
- Колесо решений принимает до восьми собственных вариантов, а победивший вариант показывается на весь экран с нарисованной анимацией и конфетти.
- Добровольный виджет примерного расстояния. Запрос геолокации открывается непосредственно по нажатию пользователя, интерфейс объясняет разрешение и восстановление ранее запрещённого доступа. Координаты округляются до 0,1° до отправки и не раскрываются партнёру.
- Статус присутствия, светлая и тёмная темы, пять нежных обоев комнаты, адаптивная мобильная и десктопная вёрстка, рукописная стилистика и знак-сердце из переплетённых нитей.
- Все прикладные таблицы закрыты RLS; прямой доступ клиентов к таблицам отозван. Клиент работает только через проверяющие права RPC-функции. Push-ключи и endpoints доступны только серверной Edge Function, а Storage и Realtime дополнительно ограничены членством в конкретной комнате.

## Важные ограничения beta 0.6

- Удаление аккаунта ещё не подключено. Восстановление пароля уже работает в интерфейсе через Supabase Auth.
- Фирменные HTML-шаблоны подтверждения и восстановления подготовлены в `supabase/email-templates`, а повторная отправка подтверждения есть в интерфейсе. Настоящий адрес вида `LoveLoom <hello@домен>` появится только после согласованного подключения домена и собственного SMTP; до этого письма отправляет стандартный SMTP Supabase.
- Лимит одного файла в beta — 100 МБ; для голосовых сообщений — 25 МБ. Это защищает бесплатное хранилище от случайного переполнения.
- Аудио- и видеозвонки пока представлены экраном-заглушкой; LiveKit или другая WebRTC-инфраструктура не оплачены и не подключены.
- Push для новых сообщений реализован с контрольным уведомлением и автоматическим восстановлением устаревшей подписки. После публикации полную доставку в фоне и после долгого сна всё ещё нужно проверить на ваших Android/iPhone. Уведомления о входящем звонке появятся одновременно с подключением самой инфраструктуры звонков.
- Ссылка «Создатель T&A» открывает будущий экран владельца, но облачная админ-панель пока намеренно отключена. Секрет из переписки не встроен в код.
- Оплата 199 ₽ будет добавлена отдельным этапом. Сейчас комнаты создаются бесплатно и не имитируют оплату.
- GitHub Pages beta работает только с интернетом. Manifest и сетевой Service Worker позволяют установить приложение и принимать Push без кэширования личных данных. Вибрация зависит от API конкретного браузера и может быть недоступна на части устройств; визуальная анимация при этом остаётся. Safari и реальные Android/iOS-устройства требуют отдельной ручной проверки перед стабильным релизом.
- Сквозного шифрования переписки нет. Доступ изолирован правилами базы и учётными записями участников.

## Безопасность и жизненный цикл комнаты

Облачная схема находится в `supabase/migrations`. Профили, комнаты, участники, записи, сообщения, медиа, капсулы, сад, геолокация и игры разделены по `room_id`. Все операции проверяют текущего пользователя на стороне PostgreSQL. Создание и вход блокируют строку комнаты на время проверки, поэтому одновременные запросы не могут добавить третьего участника. Попытки подбора пароля ограничены. Push-endpoints нельзя читать из браузера; сервер проверяет автора и свежесть сообщения и не допускает повторную доставку одного сообщения.

При выходе приглашённого участника удаляются сообщения, метаданные медиа, капсулы, сад, общие записи, координаты и игровые данные, увеличивается версия истории и сбрасывается дата отношений. При удалении комнаты создателем каскадно удаляются данные комнаты и связанный секрет Vault. Эти действия необратимы в интерфейсе.

Не публикуйте `.data`, локальные базы, служебные ключи Supabase или переменные окружения. Publishable key допускается в браузере и не является служебным ключом. Service-role key в репозитории отсутствует.

## Локальный запуск

Нужен Node.js 24 или новее.

```sh
npm ci
npm run dev
```

Откройте `http://127.0.0.1:3000`. Обычный локальный режим использует SQLite-адаптер для разработки; публичная сборка GitHub Pages создаётся отдельной командой и использует Supabase:

```sh
npm run test:beta
```

Переменные `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` можно задать при сборке. Для текущей публичной beta URL проекта и безопасный publishable key также имеют явные значения по умолчанию, чтобы GitHub Pages собирался без секретов.

## Проверки

```sh
npm run typecheck
npm test
npm run build
npm run test:browser
npm run test:beta
```

- Серверные тесты локального адаптера проверяют регистрацию, уникальность кода, лимит участников, изоляцию комнат, сохранение после открытия базы, удаление истории и права владельца.
- SQL-интеграционный сценарий Supabase проверяет создание комнаты, запрет совпадающего пароля, вход второго и отказ третьему, общие сообщения и записи, выход с очисткой истории, повторный вход и удаление комнаты вместе с Vault-секретом.
- Проверка статической beta открывает настоящий начальный экран в Chromium на десктопе и мобильном viewport, проверяет форму регистрации, шрифты, отсутствие переполнения, сохранение темы и ошибки ресурсов.

Подробный отчёт находится в `QA.md`.

## Структура

- `app` — страница, стили и API локального режима.
- `components/loveloom.tsx` — общий адаптивный интерфейс.
- `components/moments.tsx` — альбом, капсулы, сад, тактильность и медиа-сообщения.
- `components/games-experience.tsx` и `lib/game-content.ts` — полноэкранные игры, колесо и единый каталог 80 вопросов.
- `lib/cloud.ts` — браузерный адаптер Supabase для GitHub Pages.
- `lib/collaboration.ts` и `docs/beta-07-collaboration-architecture.md` — выключенные контракты и безопасный план звонков/совместного просмотра версии 0.7.
- `lib/media.ts`, `lib/voice.ts`, `lib/push.ts` и `lib/garden.ts` — мобильные форматы, переносимая запись звука, Push и единые пороги роста сада.
- `lib/store.ts` — SQLite-адаптер локальной разработки.
- `lib/types.ts` — контракты данных.
- `supabase/migrations` — облачная схема, RLS и RPC-функции.
- `scripts/build-beta.mjs` — статическая облачная сборка.
- `scripts/beta-smoke.mjs` — браузерная проверка начального экрана beta.
- `tests` — проверки локальных серверных правил.
- `ASSETS.md` — происхождение графики и шрифтов.

Следующий этап: удаление аккаунта и фирменный SMTP после подключения домена; звонки и совместный YouTube остаются выключены до отдельного согласования инфраструктуры, правил и расходов.
