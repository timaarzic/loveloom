# Проверка LoveLoom beta 0.4

Дата: 27 сентября 2026 года. Среда: Node.js 24, Linux, Chromium 153, Supabase Postgres 17.

## Автоматические проверки

- `npm run typecheck` — проверка TypeScript.
- `npm test` — 13 проверок локального адаптера: регистрация, уникальность пароля комнаты, лимит участников, изоляция данных, сохранение, очистка истории, права владельца, конфликты записей, приватность игр, согласие на геолокацию, хранение секретов, администратор и ограничение попыток.
- `npm run build` — production-сборка локального Next.js-приложения.
- `npm run test:browser` — две независимые локальные сессии Chromium, полный сценарий комнаты, новые виджеты, сохранение обоев и мобильная/десктопная вёрстка.
- `npm run test:beta` — статическая облачная сборка под `/loveloom` и проверка настоящего начального экрана на 1440×1060 и 390×844.

## Проверено в Supabase

В отдельном интеграционном прогоне были созданы временные пользователи и выполнен полный цикл:

1. Первый пользователь создаёт комнату.
2. Повторное создание с тем же паролем отклоняется.
3. Второй пользователь входит в комнату.
4. Третий пользователь не может войти в заполненную комнату.
5. Сообщение, общая запись, расстояние и игра сохраняются и доступны только участникам.
6. Приглашённый участник выходит; история удаляется, версия комнаты меняется.
7. Он повторно входит по прежнему паролю в пустую историю.
8. Создатель удаляет комнату; каскадные данные и секрет Vault удаляются.

Отдельный откатываемый прогон beta 0.4 дополнительно проверил:

1. Создание закрытого альбома и голосового сообщения с привязанными метаданными Storage.
2. Доступ второго участника комнаты к альбому и медиа-сообщению.
3. Скрытие тела капсулы до времени открытия.
4. Общее состояние виртуального сада.
5. Разрешение собственного и запрет чужого realtime-топика тактильности.
6. Разрешение пути Storage только участнику нужной комнаты.
7. Отсутствие прямого `SELECT` к таблице медиа и запрет анонимного вызова RPC.

Транзакция проверки была полностью откачена. Исходные аккаунты и комнаты сохранились. Все одиннадцать прикладных таблиц имеют включённый RLS, а права прямого чтения и изменения таблиц для `anon` и `authenticated` отозваны. Клиентские операции доступны только через функции с обязательной проверкой `auth.uid()`, членства, роли владельца и версии комнаты. Для приватного bucket созданы отдельные политики чтения, загрузки и отката загрузки; для Realtime — отдельные политики Broadcast и Presence.

## Проверено на начальном экране beta

- Приложение открывается на форме входа, а не в демонстрационной комнате.
- Поля почты и пароля редактируются; доступна вкладка регистрации с именем и подтверждением возраста 14+.
- Демо-панель переключения ролей отсутствует.
- Рукописные шрифты и локальные ресурсы загружаются без ошибок.
- На десктопе и телефоне нет горизонтального переполнения.
- Выбранная тема сохраняется после перезагрузки.
- Виджеты тактильности, сада, альбома и капсулы корректно перестраиваются на ширине 390 px.
- Пять обоев комнаты переключаются и сохраняются после перезагрузки.
- Системные поля выбора файла скрыты; чат на телефоне показывает отдельные кнопки скрепки, микрофона и отправки.
- Сессия Supabase настроена с `persistSession` и `autoRefreshToken`; состояние комнаты каждый раз читается из базы после восстановления сессии.

## Границы проверки

Среда автоматического Chromium блокирует исходящие запросы к домену Supabase, поэтому браузерный cloud-сценарий внутри неё разделён на две независимые проверки: интерфейс проверен Chromium, а реальная авторизация и весь жизненный цикл комнаты — Supabase-клиентом и SQL-интеграционным сценарием. После публикации нужно дополнительно пройти регистрацию и вход с двух реальных устройств по адресу GitHub Pages.

Это не независимый аудит безопасности. Пока не проверены физические Android/iOS-устройства, Safari, установка PWA, мобильная клавиатура, реальная вибрация, GPS и нагрузка. База, права и метаданные медиа проверены в Supabase, но реальную передачу крупных бинарных файлов нужно дополнительно пройти с двух физических устройств после публикации. Восстановление пароля, удаление аккаунта, звонки, фоновые уведомления, оплата, фирменный SMTP и облачная админ-панель не входят в готовые функции beta 0.4.
