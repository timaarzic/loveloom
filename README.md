# LoveLoom · beta 0.2

Первый работающий этап приложения для двух участников. Создание комнат бесплатно. Платёжного экрана и реальных списаний нет.

## Публичная дизайн-бета

В репозитории подготовлена отдельная версия для GitHub Pages. Она нужна, чтобы оценивать оформление и переходы с телефона или компьютера. Верхняя панель позволяет открыть комнату, лобби, экран входа и переключить тестовую роль между Алексом и Сашей.

Дизайн-бета использует только вымышленные примеры. Изменения сохраняются в браузере посетителя и не синхронизируются с другим устройством. Она не отправляет запросы к `/api`, не содержит сервер, базу, админку или настоящую авторизацию. Не вводите в неё реальные личные данные.

```sh
npm run test:beta
```

Команда собирает статический предпросмотр с адресным префиксом `/loveloom` и проверяет его в мобильном и десктопном режимах. Workflow `.github/workflows/pages.yml` повторяет эту сборку при обновлении ветки `main` и публикует каталог `out` в GitHub Pages.

Это локальная версия для проверки интерфейса и логики. Сервис ещё не опубликован. Supabase, Vercel, почтовые сервисы, LiveKit и платёжные системы не подключались.

## Запуск на компьютере

Нужен Node.js 24 или новее.

1. Распакуйте архив и откройте терминал в папке `loveloom`.
2. Выполните `npm ci`.
3. Выполните `npm run dev`.
4. Откройте `http://127.0.0.1:3000`.

Для проверки пары откройте приложение в двух разных браузерах или в обычном и приватном окне. Зарегистрируйте два тестовых аккаунта. Первым создайте комнату, вторым войдите по её паролю. Подтверждение почты ещё не подключено, поэтому используйте тестовые адреса вида `alex@example.test` и отдельные тестовые пароли.

Сервер слушает только локальный компьютер. Открыть приложение на другом телефоне через интернет пока нельзя. Публикация и внешние подключения требуют отдельного согласования.

## Что уже работает

- Логотип: сердце из множества переплетённых нитей; отдельная надпись LoveLoom.
- Русский интерфейс, адаптивная мобильная и десктопная вёрстка, светлая и тёмная темы.
- Рисованный стиль: рукописные числа и заголовки, бумажный фон, пастельные стикеры и кнопки с живым контуром.
- Шесть быстрых виджетов разделов и настройка карточек главной страницы на каждом устройстве.
- Регистрация по адресу почты и паролю; вход и выход из аккаунта.
- Бесплатное создание комнаты и вход по уникальному коду. Коды нечувствительны к регистру.
- Один аккаунт в одной комнате, максимум два участника. Ограничения проверяет сервер и база, не только интерфейс.
- Два счётчика: отношения и возраст комнаты, общий часовой пояс, личное имя партнёра.
- Текстовый чат: история, подгрузка старых сообщений, синхронизация двух сессий опросом сервера раз в две секунды, статус присутствия.
- Календарь, текстовые воспоминания, заметки, желания, списки фильмов и музыки.
- Защита записей от незаметной перезаписи при одновременном редактировании.
- Четыре базовые игры с небольшим набором вопросов. Ответы партнёра скрыты до ответа обоих. В игре «Знаю тебя» каждый указывает свой выбор и прогноз выбора партнёра. В викторине правильный ответ раскрывается после завершения.
- Приблизительное расстояние с добровольным разовым разрешением каждого. Координаты округляются до 0,1° ещё в браузере и повторно на сервере. Снимок состояния не раскрывает партнёру сами координаты. Отзыв разрешения удаляет сохранённое местоположение.
- При выходе приглашённого участника общие записи, сообщения, геолокация и игровые ответы удаляются у обоих. Комната с прежним паролем остаётся у создателя. Повторный вход начинает пустую историю.
- Создатель может удалить комнату у обоих. Вход в аккаунт после обычного выхода сохраняет комнату.
- Ссылка «Создатель T&A», отдельная авторизация администратора, список пользователей по комнатам без личной переписки и паролей.
- Манифест приложения, иконки и сетевой service worker. Данные не кешируются для офлайн-работы. Установка PWA на реальных телефонах ещё не проверена.

Эти функции не считаются готовыми, даже если в интерфейсе есть подпись «Позже»:

3. Загрузка фото и видео; проверка файлов, приватная выдача медиа и автоматическое удаление старейших вложений при заполнении лимита.
4. Согласованный экспорт общей истории с подтверждением обоих участников.
5. Web Push и полноценные уведомления. Пока нет фоновых оповещений и входящих звонков.
6. Аудио- и видеозвонки: согласование инфраструктуры, проверка соединений из России, обработка устройств и разрешений.
7. Расширение банка вопросов, функциональности игр и воспоминаний.
8. Оферта и политика обработки данных для публичного продукта, резервные копии и согласованный процесс удаления, проверка региональных требований к размещению данных.
9. Публикация, домен, нагрузочная проверка и реальные Android/iOS-устройства.
10. Оплата 199 ₽ — только когда владелец решит её подключить. Сейчас все комнаты имеют статус `free`; это не имитация успешной оплаты. Платёжный адаптер, webhook и чеки пока не реализованы.

Поиск, редактирование и удаление отдельных сообщений не предусмотрены согласованной первой версией. Остальные идеи из ТЗ — голосовые, капсула времени, письма, отдельный альбом, настроение, сад, дневник и перестановка виджетов — остаются последующими обновлениями.

## Локальные данные и безопасность

Стек текущего этапа: Next.js, React, TypeScript, собственная CSS-система, Node.js SQLite. SQLite используется только как локальный проверочный адаптер, а не как замена утверждённой облачной архитектуры.

Данные хранятся в `.data/loveloom.sqlite`. Секрет шифрования кодов — в `.data/local.key`. Они не включены в исходный архив. Не публикуйте `.data`, тестовые базы или переменные окружения.

Пароли аккаунтов и администратора хешируются с индивидуальной солью через scrypt. Сеансы используют случайные токены и HttpOnly/SameSite-cookie; в базе хранится хеш токена. Пароли комнат зашифрованы AES-GCM, а их уникальность проверяется по HMAC. Права и версия истории проверяются перед изменениями. Для запросов изменения состояния используется защита по Origin и CSRF-токену. Попытки входа и частота действий ограничены.

В приложение не встроен какой-либо пароль администратора из переписки. Нет механизма «первый посетитель становится администратором».

Сквозное шифрование переписки не реализовано. Текущую версию нельзя считать проверенным публичным сервисом для хранения личных данных. Удаление не имеет функции восстановления в приложении; это не гарантия уничтожения копий, которые пользователь сохранил вне приложения, или отсутствия технических следов на локальном диске.

Запуск production-сборки блокирует работу API без `LOVELOOM_LOCAL_ALPHA=1`. Даже с этим флагом адаптер рассчитан на локальный постоянный диск и localhost: его нельзя размещать на Vercel как готовую облачную базу.

## Доступ владельца

1. На своём компьютере выполните `npm run admin:invite`.
2. В терминале появятся одноразовый секрет и инструкции запуска. Не отправляйте их в чат и не публикуйте.
3. Запустите локальный сервер с переменной `LOVELOOM_ADMIN_SETUP_TOKEN`, как указано в инструкции.
4. Откройте показанную локальную ссылку и придумайте отдельный пароль от 14 символов.
5. После настройки уберите переменную и перезапустите сервер. База не позволит повторную регистрацию владельца.

Скрипт печатает команду для bash. В PowerShell переменная задаётся в текущем терминале через `$env:LOVELOOM_ADMIN_SETUP_TOKEN='значение_из_терминала'`; далее `npm run dev`. Это не пароль комнаты. MFA и восстановление владельца — следующий этап.

## Проверки

```sh
npm run typecheck
npm test
npm run test:browser
```

Браузерный сценарий сам запускает production-сборку на loopback-порту 3100, использует отдельную временную базу, создаёт тестовых участников и закрывает свои процессы по завершении. Для Linux в devDependencies включён тестовый Chromium. На Windows/macOS перед браузерной проверкой выполните `npx playwright install chromium`.

Снимки экрана в папке `preview` показывают вымышленные тестовые аккаунты и записи, созданные через приложение, а не реальные данные пары. В архив не включены базы и сеансы тестовых прогонов. Пароли в исходниках тестов — синтетические значения только для временных тестовых аккаунтов.

## Структура

- `app` — страница, общие стили и серверные API.
- `components/loveloom.tsx` — экраны первого этапа.
- `lib/store.ts` — локальная база и серверные правила.
- `lib/types.ts` — контракты данных.
- `public` — знак, иконки и сетевой service worker.
- `tests` — проверки доступа, жизненного цикла комнаты и приватности игр.
- `scripts` — локальное приглашение администратора и браузерная проверка.
- `ASSETS.md` — происхождение графики и шрифтов.

Следующий технический этап — выделить отдельные экранные компоненты и подключить согласованный облачный адаптер, сохранив проверенные правила доступа и жизненного цикла комнаты.
