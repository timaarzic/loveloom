# Проверка LoveLoom beta 0.6

Дата: 3 октября 2026 года. Среда: Node.js 24, Linux, Chromium 153, Supabase Postgres 17.

Код 0.6 проверяется в отдельной ветке. Публичная GitHub Pages beta и рабочая схема базы остаются на 0.5 до отдельной команды на публикацию.

## Автоматические проверки

- `npm run typecheck` — проверка TypeScript.
- `npm test` — 22 проверки: регистрация, уникальность пароля комнаты, лимит участников, изоляция данных, сохранение, очистка истории, права владельца, конфликты записей, приватность игр, все 80 вопросов, ответы на сообщения, реакции, курсоры прочтения, лимит 1000 сообщений, точное совпадение победителя колеса с сектором под стрелкой, соответствие SQL-каталога приложению, согласие на геолокацию, хранение секретов, администратор, ограничение попыток, стадии сада, мобильные форматы фотографий и корректный WAV-контейнер голосовых.
- `npm run build` — production-сборка локального Next.js-приложения.
- `npm run test:browser` — две независимые локальные сессии Chromium, полный сценарий комнаты, плавная отправка, ответы и реакции в чате, статус прочтения, непрочитанный бейдж, общий игровой раунд, колесо с восемью вариантами, фирменным знаком и проверкой победителя под стрелкой, запрос геолокации по нажатию, виджеты, сохранение обоев и мобильная/десктопная вёрстка.
- `npm run test:beta` — статическая облачная сборка под `/loveloom` и проверка настоящего начального экрана на 1440×1060 и 390×844.

## Проверено в Supabase

В отдельном интеграционном прогоне были созданы временные пользователи и выполнен полный цикл:

1. Первый пользователь создаёт комнату.
2. Повторное создание с тем же паролем отклоняется.
3. Второй пользователь входит в комнату.
4. Третий пользователь не может войти в заполненную комнату.
5. Сообщение, общая запись, расстояние и игра сохраняются и доступны только участникам.
6. Приглашённый участник выходит; история удаляется, версия комнаты меняется.
7. Он повторно входит по прежнему паролю в пустую историю.
8. Создатель удаляет комнату; каскадные данные и секрет Vault удаляются.

Отдельный откатываемый прогон beta 0.4 дополнительно проверил:

1. Создание закрытого альбома и голосового сообщения с привязанными метаданными Storage.
2. Доступ второго участника комнаты к альбому и медиа-сообщению.
3. Скрытие тела капсулы до времени открытия.
4. Общее состояние виртуального сада.
5. Разрешение собственного и запрет чужого realtime-топика тактильности.
6. Разрешение пути Storage только участнику нужной комнаты.
7. Отсутствие прямого `SELECT` к таблице медиа и запрет анонимного вызова RPC.

Транзакция проверки была полностью откачена. Исходные аккаунты и комнаты сохранились. Все одиннадцать прикладных таблиц имеют включённый RLS, а права прямого чтения и изменения таблиц для `anon` и `authenticated` отозваны. Клиентские операции доступны только через функции с обязательной проверкой `auth.uid()`, членства, роли владельца и версии комнаты. Для приватного bucket созданы отдельные политики чтения, загрузки и отката загрузки; для Realtime — отдельные политики Broadcast и Presence.

Для beta 0.5 в рабочем Supabase дополнительно применена миграция Push и развёрнута JWT-защищённая Edge Function `loveloom-push`. Три серверные таблицы подписок, VAPID-ключа и дедупликации имеют RLS; роли `anon` и `authenticated` не могут читать их напрямую, а `service_role` используется только внутри функции. Клиентские RPC разрешают подписанному пользователю добавить или удалить собственный endpoint и ограничивают аккаунт пятью устройствами.

Для исправления beta 0.5 в рабочей базе добавлен защищённый курсор чтения чата для каждого участника. Прямой доступ к таблице отозван; RPC подсчёта и отметки прочтения проверяют авторизацию, членство в комнате и текущую версию истории. Существующая переписка при установке исправления отмечена прочитанной, поэтому бейдж считает только новые сообщения. Отдельный RPC позволяет браузеру проверить наличие собственной Push-подписки, не раскрывая endpoints других устройств.

Edge Function `loveloom-push` обновлена до версии 2: она удаляет просроченные endpoints, возвращает число успешных доставок и умеет отправить контрольное уведомление текущему пользователю сразу после включения. Холодный запуск проверен отдельным запросом: среда функции загрузилась, а анонимный запрос получил `401`. Полную цепочку «разрешение браузера → контрольное уведомление → сообщение партнёра → системное уведомление» необходимо пройти после публикации на двух физических устройствах; без пользовательского разрешения создавать Push-подписку нельзя.

SQL-миграция beta 0.6 была целиком выполнена в рабочем PostgreSQL внутри явной транзакции с последующим `ROLLBACK`. База успешно разобрала каталог из 80 вопросов, новые связи ответов, реакции и функции синхронизации. После отката отдельно подтверждено отсутствие новой таблицы и колонки в рабочей схеме; опубликованная beta 0.5 не изменилась. Сам файл миграции дополнительно сравнивается тестом с TypeScript-каталогом вопрос в вопрос.

## Проверено на начальном экране beta

- Приложение открывается на форме входа, а не в демонстрационной комнате.
- Поля почты и пароля редактируются; доступна вкладка регистрации с именем и подтверждением возраста 14+.
- Демо-панель переключения ролей отсутствует.
- Рукописные шрифты и локальные ресурсы загружаются без ошибок.
- На десктопе и телефоне нет горизонтального переполнения.
- Выбранная тема сохраняется после перезагрузки.
- Виджеты тактильности, сада, альбома и капсулы корректно перестраиваются на ширине 390 px.
- Кнопка тактильности использует фирменное сердце, а розовые частицы создаются только после успешного сигнала.
- Полноэкранные сердца и нарисованные поцелуи создаются только вместе с тем же успешным эфемерным сигналом; исходные волны вокруг логотипа сохранены.
- Пороги сада 30, 50 и 100 и распознавание JPEG/HEIC/HEIF проверяются отдельными модульными тестами.
- Сервер хранит не более трёх последних капсул на комнату.
- Пять обоев комнаты переключаются и сохраняются после перезагрузки.
- Системные поля выбора файла скрыты; чат на телефоне показывает отдельные кнопки скрепки, микрофона и отправки.
- Сессия Supabase настроена с `persistSession` и `autoRefreshToken`; состояние комнаты каждый раз читается из базы после восстановления сессии.
- Service Worker включён в статическую сборку `/loveloom`, не кэширует личные данные, принимает Push и открывает вкладку чата по нажатию на уведомление.
- Вне чата клиент регулярно получает серверный счётчик непрочитанных сообщений и показывает красный бейдж над иконкой; открытие чата сохраняет курсор прочтения в базе.
- Диалог расстояния определяет состояние разрешения геолокации, вызывает системный запрос только по нажатию и показывает инструкцию для ранее запрещённого доступа.
- Новая запись голоса кодируется в mono PCM WAV 16 кГц, а плеер сначала получает файл целиком в Blob, чтобы Safari не зависел от Range-запроса подписанной ссылки Storage.
- В форме входа появился безопасный сценарий восстановления: письмо Supabase, одноразовый recovery-сеанс и проверка совпадения нового пароля.
- В каждой из четырёх игр ровно 20 уникальных вопросов; предыдущий вопрос не повторяется сразу, а ответы партнёра остаются скрытыми до завершения раунда обоими.
- Игровой раунд открывается отдельным модальным экраном с удержанием фокуса, адаптируется под 390 px и уважает системное уменьшение анимации.
- Колесо принимает от двух до восьми вариантов, блокирует девятый, выбирает через `crypto.getRandomValues`, показывает результат на весь экран и создаёт 36 частиц конфетти.
- Ответы на сообщения, смена/снятие реакции и статус прочтения проверены в двух независимых браузерных сессиях. События Realtime передают только сигнал обновления; содержимое повторно читается через авторизованный RPC.

## Границы проверки

Среда автоматического Chromium блокирует исходящие запросы к домену Supabase, поэтому браузерный cloud-сценарий внутри неё разделён на две независимые проверки: интерфейс проверен Chromium, а реальная авторизация и весь жизненный цикл комнаты — Supabase-клиентом и SQL-интеграционным сценарием. После публикации нужно дополнительно пройти регистрацию и вход с двух реальных устройств по адресу GitHub Pages.

Это не независимый аудит безопасности. Пока не проверены все физические Android/iOS-устройства, Safari, системная доставка Push после долгого сна, мобильная клавиатура, реальная вибрация, GPS и нагрузка. База, права и метаданные медиа проверены в Supabase; отображение HEIC зависит от поддержки браузера — при её отсутствии доступен оригинал. Удаление аккаунта, звонки, совместный YouTube, Push входящего звонка, оплата, собственный SMTP-домен и облачная админ-панель не входят в готовые функции beta 0.6.
